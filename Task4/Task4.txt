Osago-aggregator

API для core-app:
POST /osago/request — отправить заявку
GET /osago/request/{id}/offers — получить все полученные предложения

Интеграция между core-app и osago-aggregator:

REST API для инициализации заявки.

Kafka для асинхронной доставки событий, пусть будет два: OfferReceived, OfferFailed.

Будем также использовать REDIS c TTL 60 сек для храния состояние заявок

Взаимодействие core-app с osago-aggregator будет происходить следующим образом:
Пользователь через UI делает POST /osago в core-app
core-app валидирует и обогащает заявку, затем вызывает REST метод POST /osago/request в osago-aggregator

Потом osago-aggregator:
сохраняет заявку в своём хранилище
отправляет синхронные запросы на создание заявки в страховые компании

запускает асинхронный процесс опроса предложений (до 60 сек из задания)
по мере поступления предложений публикует события OfferReceived в Kafka

core-app подписан на Kafka-топик и получает предложения в реальном времени.
core-app передаёт их пользователю через WebSocket по GET /osago/{id}/stream.


Соотвественно API для фронта в core-app

POST /osago — создать заявку
GET /osago/{id}/offers — получить предложения
GET /osago/{id}/stream — WebSocket для получения предложений в реальном времени

Интеграция фронта и core-app

REST будет для CRUD в данном случае создании заявки
WebSocket — для real-time получения предложений по мере готовности

Также при взаимодействии core-app с osago-aggregator попробуем заюзать все паттерны из курса:)))

1. Установим Timeout (60 секунд) — на каждый REST-запрос к страховой компании
Это ограничивает общее время ожидания и предотвращает зависание обработки заявки
Поскольку SLA требует ответа максимум за 60 секунд, после таймаута заявка считается проваленной для этой страховой

2. Retry, если REST-запрос к API страховой компании завершился временной ошибкой (5xx или timeout),
выполняется повторная попытка. Количество ретраев ограничим ну и не превышает 60 секунд общего времени с момента запроса

3. Circuit Breaker — для каждой страховой компании будем создавать отдельный circuit breaker
При большом количестве ошибок или таймаутов цепь прерывается, нет смысла так как кртичность 60 секунд для бизнеса, так что просто будем отдавать что-то типо Повторите попытку позже

4. Rate Limiting для каждой страховой компании устанавливается индивидуальный лимит запросов (о нем узнаем от бизнеса)
